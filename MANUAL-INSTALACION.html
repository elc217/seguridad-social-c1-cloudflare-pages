LGSS Seguridad Social C1

Manual de instalación y distribución

Elaborado para: Comunidad de Alumnos de «Escuela Ciudadana de Administración Pública» (ECAP)

1. Antes de empezar

La aplicación se distribuye con el mismo contenido en PWA, Android, iOS, Windows y macOS. El texto legal, las tarjetas y las preguntas están incluidos en cada build.

Web/PWA
Cloudflare Pages
Móvil
APK / IPA
Escritorio
EXE / DMG

2. PWA local

cd version-unificada
npm install
npm start

Abrir http://127.0.0.1:8766. Para detener el servidor, pulsar Ctrl+C.

3. Publicación Cloudflare Pages

cd version-unificada
npm run package

Subir lgss-c1-cloudflare.zip mediante Direct Upload. No configurar comando de build: es un sitio estático ya preparado.

Comprobación: el ZIP contiene la aplicación, datos, recursos, logotipo ECAP y fuentes locales necesarias.

4. macOS

Intel (x64)

Archivo: LGSS Seguridad Social C1-1.0.0.dmg

Abrir el DMG y arrastrar la aplicación a Applications.

Apple Silicon (arm64)

Archivo: LGSS Seguridad Social C1-1.0.0-arm64.dmg

Abrir el DMG y arrastrar la aplicación a Applications.

Primera apertura: los DMG no llevan certificado Apple de distribución. Si macOS muestra una advertencia, hacer Ctrl+clic sobre la aplicación y elegir Abrir.

5. Windows

Descargar y descomprimir el artifact windows-installer de GitHub Actions.

Ejecutar:

LGSS Seguridad Social C1 Setup 1.0.0.exe

Seguir el asistente. El archivo blockmap acompaña al instalador para actualizaciones y no se ejecuta manualmente.

6. Android

Descargar y descomprimir android-apk. Transferir app-debug.apk al dispositivo y abrirlo.

  1. Autorizar temporalmente la instalación desde esa fuente si Android lo solicita.
  2. Confirmar la instalación.
  3. Abrir LGSS Seguridad Social C1.

Es un APK de depuración para pruebas y distribución directa, no un paquete publicado en Google Play.

7. iOS

Descargar y descomprimir ios-ipa. El IPA de CI se genera sin firma de distribución.

Para instalarlo en un dispositivo físico hay que firmarlo con una cuenta Apple válida mediante Xcode, TestFlight u otro flujo autorizado. El archivo demuestra que el proyecto compila, pero no sustituye la firma Apple.

9. Google Drive

La sincronización es opcional y utiliza el Google Drive de cada usuario. Cada usuario pulsa el botón, elige su cuenta y acepta el permiso oficial. No se debe compartir ningún client secret.

  • Scope mínimo: drive.appdata.
  • Solo se sube progreso.
  • La biblioteca y las preguntas permanecen locales.
  • La cuenta debe ser usuario de prueba mientras OAuth esté en pruebas.

10. Validación técnica

cd version-unificada
npm test
npm run package

La suite actual contiene 18 pruebas. Antes de distribuir una nueva versión conviene comprobar navegación, tarjetas, test, exportación, importación y sincronización.
